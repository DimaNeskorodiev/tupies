## Security and reliability changes

- Device session protocol v2 binds proof to the target engine node and fingerprint. Engine metadata advertises explicit protocol versions. Older clients cannot silently fall back; native apps retain their device key and explain the required update.
- Engine pairing v2 uses fresh P-256 ECDH with signed, code-bound client/target transcripts. Links specifying engine TLS require the correct identity key before the first HTTP request. Credentialed engine HTTP refuses redirects and has deadlines.
- A sealed, fsync-backed engine-local security journal owns workspace-key epochs, engine grants and sticky device/engine revocations. Revoking an engine removes its grant and rotates the workspace key atomically. Authorized offline peers recover individually wrapped replacement keys. The plaintext `workspace.key` is a repairable mirror. Revocation cannot erase data already copied by a formerly trusted engine.
- Commands, skill scripts and language servers use private per-bot process homes outside model-writable workspaces, with a stripped environment and explicit trusted runtime path. Python user-site loading and automatic Git helpers/hooks/fsmonitor are disabled. Editing Git startup metadata requires exact approval. Approved commands still have host-account privileges.
- Unlinking suspends copied automation locally. Explicit promotion does not take ownership of a copied ChatGPT grant: only fresh validated sign-in or verified same-home relinking restores that ownership. Topology changes quiesce channel polls and block admission. One-time routine schedule advancement now commits atomically with run/message admission, so a failed save or unlink race cannot consume an unstarted job.
- File sync invalidates cache state after publication and fingerprints inode/change time, so an immediate external edit is detected. Blob availability revalidates bounded bytes. Unscanned local versions are preserved as checked, idempotent conflict copies; failed preservation or missing blobs cannot acknowledge a document/cursor. Three deterministic filesystem races failed before the fix and pass afterward.
- Store initialization refuses to generate a replacement key over retained state or silently bootstrap after state loss. Offline snapshot/verify/restore commands preserve the entire runtime tree, validate hashes and credentials, reject unsafe files and refuse a running engine. Snapshots contain plaintext private data and keys; protect them independently.
- Disposable realistic-state verification exercises concurrent work, valid polling, verified full restore and SIGKILL during model/approval work. Recovery preserves committed artifacts/partial output and never replays side effects.
- Native build 4 can include an official checksum-pinned Node 22.23.4 runtime, production dependencies, fonts/notices and engine source. New managed data lives outside the signed app. Running existing engines and saved developer installations take precedence. Relaunch resumes only the associated managed engine identity; deliberately removed local pairings stay removed.

The 29 October deployment coordinated both engines and apps. Legacy engine links pause until explicitly relinked using their existing identities and data. A source rollback must not weaken v2 security or restore old revocation state. Restoring an old hub backup requires an offline rekey/relink procedure; see [security](../security.md), [sync](../sync.md) and [operations](../operations.md).

## Grok functionality and UX work

- Owner-facing conversation search is visible in the desktop sidebar and phone header, with Cmd/Ctrl+K and scoped bot/room menus. Results include excerpts/dates and open the exact message. Drafts survive navigation in the current page session. Search is local and bounded; partial coverage is disclosed.
- Direct-chat **Add direction** changes the active task at a model boundary. Updates have idempotent identities and queued/applied/cancelled transcript status. Superseded, unadmitted model actions are skipped; an already admitted action may finish. Original checks, model/capability snapshots and permissions remain fixed. Pending questions/approvals must be resolved first. Abandoning a required outcome requires Stop and a revised task.
- Actual browser testing found and fixed same-chat result focus and phone bottom-follow overriding the selected result. At 320 px, the matched message is visible below the header and the unsent draft remains intact. Desktop guidance was observed progressing from queued to applied to one completed answer.
- Successful exact history/note reads now satisfy declared source checks. Searches, failed reads and ambiguous IDs remain refused. The previous allowlist incorrectly failed useful work after real original-source retrieval.
- ChatGPT subscription inference follows the current official Responses contract: namespaced tools, validated returned names/namespaces, streamed non-stored requests and no unsupported output-token parameter. The requested output allowance is an estimate; bounded response transport and task/time/tool admission remain enforced.
- Provider failure observability persists only a static allowlisted code, origin and numeric local/upstream statuses in the run and bounded history. It preserves the real HTTP status before local error mapping. Synthetic retention exposes the sanitized fields without raw responses, credentials or custom error properties; cancellation/local callback errors stay separate. No retry or side-effect replay was added.

Interactive signed-in browser work/takeover, credential handoff forms, continuous live voice, native device actions, App Intents/Live Activities, media creation and general event triggers remain separate feature programs.
