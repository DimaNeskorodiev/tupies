## Decision boundary

Passing Tupies regressions cannot establish identical functionality, equal usability, or market leadership. Current Grok Bot documentation describes capabilities Tupies does not implement. A release can be ready for its stated self-hosted, single-owner scope while full Grok parity remains unfinished. Both claims need their own evidence.

Official documentation establishes advertised behavior, subject to rollout and account availability. No Grok account, paid model session, or side-by-side runtime was exercised in this comparison. The package investigation does not expose Grok's backend retrieval, compaction, reasoning loop, or task-success rate.

## Release acceptance gates

Every scenario needs an observed result, build/source identity, environment, repeatable steps and retained non-private evidence. Mark unavailable capabilities as **not tested** or **not supported**, never passed. Fixtures test mechanics; real models test whether the product selects the right actions.

1. **Install to first useful result:** fresh installation, local/remote pairing, wrong link/pin, unreachable engine, revoked device, provider failure and recovery. Complete a task without undocumented setup. Test existing-install upgrade without losing connections or drafts.
2. **Message reliability:** send text and attachments, navigate during admission, lose the response after acceptance, reconnect, stop during model/tool/child work and restart during approval/question. Require one admission and honest terminal status; verify room sends independently.
3. **Approval correctness:** deny and approve exact writes/integrations/commands, change configuration while waiting, revoke a session and switch engines. No stale approval, UI gesture, remembered instruction or child reply may authorize a new action.
4. **Useful finished work:** source-backed research produces a readable real document; coding edits pass an external oracle; a wrong/failed specialist blocks success; invalid or oversized attachments fail before dispatch. Preview/download/share the actual artifact on both platforms.
5. **Long-term continuity:** correct a remembered fact, add a contradictory note, revisit after several tasks/compactions, switch engines and inspect provenance. Check source freshness and private-lane exclusion; grade final answers as well as retrieval candidates.
6. **Everyday iPhone behavior:** physical keyboard show/hide, dictation permission, safe areas, sheet dismissal with unsaved text, edge Back, portrait/landscape, foreground/background, poor network, large Dynamic Type, VoiceOver, Reduce Motion/Transparency and contrast. Browser emulation cannot pass these native gates.
7. **Attention and automation:** timezone/DST/once/missed-run/busy-bot routines, home-server-only scheduling, offline phone, background delivery, denied notification permission and cold-start taps. Real APNs receipt and a queued outbox entry are different observations.
8. **Operational release:** signed installation/update, TLS/session/revocation boundaries, isolated backup/restore, realistic state size and concurrency, dependency/security review, resource use and recovery after process/host loss. Resolve or explicitly scope the existing security/operational items in the roadmap.

## Matched product study

Use the same non-private source files, bot roles, memory corrections, task wording, dates, allowed actions and independent oracles in both products. Record Grok build/account/capability rollout and Tupies model/provider/effort; Grok's managed routing means this compares complete products rather than identical models. Never reuse real secrets or let a benchmark send/publish/delete live content.

Start with the eight versioned families in [evaluation](../evaluation.md): research-to-document, coding verification, repeated compaction, memory correction, large result/image/stale edit, specialist failure, questions/refusal and send/Stop/restart. Add desktop/iPhone handoff, routine-to-notification and a logged-in website task. Record unsupported tasks as coverage gaps, not silent omissions.

Measure independently verified task completion, known false-success, source/constraint accuracy, duplicate effects, user corrections, time to useful result and delivered artifact quality. Have a person score coverage, factual support, usefulness and honesty on the existing 0–2 rubric. Repeat tasks before drawing a ranking; a three-run pilot gives raw samples and medians, not a reliable tail-latency estimate. No matched Grok or human-rated real-model result has been produced by this document.
